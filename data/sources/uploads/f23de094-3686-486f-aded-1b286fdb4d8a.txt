The difference between blocking and non-blocking code is the single most important concept in Node.js. Master this, and you understand why Node.js is fast. Let me show you what happens when code waits - and why waiting is the enemy of performance. What Blocking Code Means Blocking code stops everything until it finishes. Nothing else runs. The server freezes. Blocking Code in JavaScript javascript // BLOCKING - Nothing else runs during this const fs = require('fs'); console.log('1. Starting...'); // This blocks everything for 2 seconds const data = fs.readFileSync('big-file.txt', 'utf8'); console.log('2. File content:', data.length, 'bytes'); console.log('3. This runs AFTER the file is read'); Output: Starting... (2 second pause) File content: 1048576 bytes This runs AFTER the file is read During those 2 seconds, your server handles ZERO other requests. It's frozen. Waiting. What Non-Blocking Code Means Non-blocking code starts an operation and continues running. When the operation finishes, it comes back to handle the result. Non-Blocking Code in JavaScript // NON-BLOCKING - Code continues while file loads const fs = require('fs'); console.log('1. Starting...'); // This does NOT block fs.readFile('big-file.txt', 'utf8', (err, data) => { console.log('2. File content:', data.length, 'bytes'); }); console.log('3. This runs IMMEDIATELY, before file is read'); console.log('4. Server can handle other requests now'); Output: Starting... This runs IMMEDIATELY, before file is read Server can handle other requests now (2 seconds later) File content: 1048576 bytes No pause. No freezing. The server keeps working while waiting. The difference: Blocking makes requests wait in line. Non-blocking processes them simultaneously. Real-World Impact // BLOCKING SERVER - Handles 1 request at a time app.get('/data', (req, res) => { const data = db.querySync('SELECT * FROM users'); // Blocks for 50ms res.json(data); }); // With 100 concurrent users: // Last user waits 100 × 50ms = 5000ms (5 seconds!) // NON-BLOCKING SERVER - Handles all requests concurrently app.get('/data', async (req, res) => { const data = await db.query('SELECT * FROM users'); // Doesn't block res.json(data); }); // With 100 concurrent users: // Last user waits ~50ms (same as first user!) Blocking Operations (Sync Methods) // ❌ BLOCKING - AVOID THESE IN SERVERS // File system (sync versions) fs.readFileSync() // Blocks while reading fs.writeFileSync() // Blocks while writing fs.statSync() // Blocks while checking file stats // Crypto (sync versions) crypto.pbkdf2Sync() // Blocks while hashing crypto.randomBytesSync() // Blocks while generating random bytes // Child processes (sync versions) child_process.execSync() // Blocks while executing child_process.spawnSync() // Blocks while spawning // Compression (sync versions) zlib.gzipSync() // Blocks while compressing // JSON parsing (can block with large data) JSON.parse(largeString) // Blocks while parsing // Loops (long running) for (let i = 0; i < 1000000000; i++) { // Blocks until loop completes } Non-Blocking Alternatives // ✅ NON-BLOCKING - USE THESE // File system (async versions) fs.readFile(path, callback) // Doesn't block fs.promises.readFile(path) // Promise version // Crypto (async versions) crypto.pbkdf2(password, salt, iterations, keylen, digest, callback) // Child processes (async) child_process.exec(command, callback) // Streams (for large files) fs.createReadStream(file) // Processes chunk by chunk // Worker threads (for CPU work) const { Worker } = require('worker_threads'); The Server Performance Test Let me show you the difference with a real example. Blocking Server Example // blocking-server.js const express = require('express'); const fs = require('fs'); const app = express(); app.get('/blocking', (req, res) => { console.log(`Request ${req.query.id} started`); // This blocks for 2 seconds const data = fs.readFileSync('big-file.txt', 'utf8'); console.log(`Request ${req.query.id} finished`); res.json({ message: 'Done', size: data.length }); }); app.listen(3000, () => { console.log('BLOCKING server running on port 3000'); }); Test it with multiple requests: # Open 3 terminals, run simultaneously curl "http://localhost:3000/blocking?id=1" curl "http://localhost:3000/blocking?id=2" curl "http://localhost:3000/blocking?id=3" # Output: Request 1 started (2 second pause) Request 1 finished Request 2 started (2 second pause) Request 2 finished Request 3 started (2 second pause) Request 3 finished # Total time: 6 seconds # Each request waits for previous! -------------------------------------- Non-Blocking Server Example // nonblocking-server.js const express = require('express'); const fs = require('fs').promises; const app = express(); app.get('/nonblocking', async (req, res) => { console.log(`Request ${req.query.id} started`); // This does NOT block const data = await fs.readFile('big-file.txt', 'utf8'); console.log(`Request ${req.query.id} finished`); res.json({ message: 'Done', size: data.length }); }); app.listen(3001, () => { console.log('NON-BLOCKING server running on port 3001'); }); Test it with multiple requests: # Open 3 terminals, run simultaneously curl "http://localhost:3001/nonblocking?id=1" curl "http://localhost:3001/nonblocking?id=2" curl "http://localhost:3001/nonblocking?id=3" # Output: Request 1 started Request 2 started Request 3 started (2 seconds later) Request 1 finished Request 2 finished Request 3 finished # Total time: 2 seconds All requests finish together! Async Operations in Node.js Node.js provides three ways to handle non-blocking operations: 1. Callbacks (Oldest) const fs = require('fs'); fs.readFile('file.txt', 'utf8', (err, data) => { if (err) { console.error('Error:', err); return; } console.log('Content:', data); }); console.log('This runs immediately'); 2. Promises (Better) const fs = require('fs').promises; fs.readFile('file.txt', 'utf8') .then(data => { console.log('Content:', data); }) .catch(err => { console.error('Error:', err); }); console.log('This runs immediately'); 3.
